# Передача через закрытый GitHub

В репозиторий разрешены только файлы из манифеста `handoff/audit.py`. `.gitignore` использует закрытый список: новые файлы сначала нужно проверить и явно разрешить. Исходные документы, references, настоящая шапка и настройки, SQLite, резервные копии, PDF, скриншоты, журналы, зависимости, секреты и локальные отчёты остаются на компьютере.

Проверка кандидатов: `python handoff/audit.py`. Хеши сохраняются локально в `artifacts/handoff/manifest.json`. Автоматический поиск секретов не заменяет просмотр каждого файла.

## Когда Git и GitHub CLI установлены

В новом PowerShell, в папке проекта:

```powershell
git --version
gh --version
gh auth login --web --git-protocol https
gh auth status
```

Вход выполняется в браузере. Не отправляйте пароли, коды авторизации и токены в чат. Не используйте `gh auth token` в отчётах.

Если `.git` отсутствует, создайте локальный репозиторий. Если он уже существует — сначала проверьте корень и историю, не инициализируйте заново:

```powershell
git init -b main
git add .
git diff --cached --stat
git diff --cached
python handoff/audit.py --git
git commit -m "Prepare private RIKA-A4 handoff"
python handoff/audit.py --git
```

Проверка `--git` сверяет состав индекса и все деревья доступной истории с разрешённым списком, проверяет содержимое каждого файла. При обнаружении приватных файлов остановитесь: `.gitignore` не удаляет их из старых коммитов. Не используйте принудительную отправку или переписывание существующего репозитория без отдельного решения.

Проверьте `gh repo view rika-a4`. Если такой репозиторий уже существует — не изменяйте его и не отправляйте туда код; согласуйте другое имя. Только если GitHub подтвердил отсутствие репозитория и вход выполнен в нужный аккаунт:

```powershell
gh repo create rika-a4 --private --source . --remote origin --push
gh repo view --json url,visibility
```

Убедитесь, что видимость `PRIVATE`. Отправка кода не размещает само приложение в интернете.

Коллеге: откройте созданный репозиторий → **Settings → Collaborators → Add people**, укажите GitHub-имя коллеги и отправьте приглашение. Коллега должен принять его. Не передавайте свой аккаунт или токен.

После передачи отдельно выбирается сервер. Для SQLite нужны постоянный диск, один экземпляр приложения, регулярные резервные копии и проверка восстановления. Текущий сервер предназначен для локальной работы; до внешнего размещения нужны авторизация, HTTPS и производственный способ обслуживания Python. Никакого развёртывания эта инструкция не выполняет.
